# Partition audits

Per-partition audit framework. For each of the 27 partition groups in
`data_estimates.csv`, an audit file in `partitions/<slug>.md` records:

- **Reference verification** — is the estimate source's DOI live? does the
  Crossref/OpenAlex record match the citation in `data_sources.csv`? is there
  a newer authoritative estimate worth tracking?
- **Canonical-tree verification** — same questions for the tree paper.
- **Methods & uncertainty** — inference type, software, loci, calibration,
  support metric, divergence CIs.
- **Sub-clade coverage** — what we ship already + candidate sub-trees we
  could add, with citations and download recipes.
- **Audit trail** — every Crossref/OpenAlex call cached for reproducibility.

## File layout

```
audits/
  README.md                   ← this file
  schema.yaml                 ← machine-readable field schema (single source of truth)
  index.csv                   ← derived: one row per partition (regenerated, do not edit)
  partitions/
    <slug>.md                 ← one per partition; slug matches data_estimates.csv `group` (lowercased)
  candidates/
    <partition>_<taxon>.md    ← optional: download recipe for a proposed sub-tree
  fetched/                    ← gitignored cache of API responses
    crossref/<doi-slug>.json
    openalex/<work-id>.json
```

## Status workflow

Every audit has a `status:` field in its frontmatter:

| Status | Meaning |
|---|---|
| `stub` | Generated by `audit_partition.py init <slug>` from existing CSVs; nothing verified yet. |
| `in_progress` | Auto-verification has run; methods block at least partially filled; auditor has open questions. |
| `verified` | DOIs verified, methods complete, sub-clade gaps explicitly accepted or rejected. Ready to surface on the website. |
| `shipped` | All accepted candidate sub-trees have been downloaded, standardized, and added to `metadata.csv`. |
| `deferred` | The partition is impossible to audit right now (e.g. "Not yet represented" lineages with no tree to verify methods on). |

Advancement requires the action listed; an audit cannot skip states.

## Schema

The frontmatter schema is defined in `schema.yaml`. The lint script
(Phase B: `scripts/audit_partition.py lint`) validates every audit file
against it. Adding a field means: (1) add it to `schema.yaml`, (2) bump
`audit_version`, (3) the lint script accepts both old and new versions
until all files migrate.

Top-level keys, in canonical order:

```yaml
partition:            # must match data_estimates.csv `group`
category:             # Vertebrates | Plants | Arthropods | Other animals | Microbes & protists
audit_version: 1
status:               # stub | in_progress | verified | shipped | deferred
last_audited:         # YYYY-MM-DD
auditor:
estimate_source:      # block — DOI, verification status, newer-candidate flag, notes
canonical_tree:       # block — same for the canonical tree paper
methods:              # block — inference, software, data type, dating, support, CIs
shipped_subclades:    # list — trees already in standardized/
candidate_subclades:  # list — proposed sub-trees with citations + download recipes
website:              # block — surface flags + badge
api_calls:            # list — audit trail (auto-populated)
```

See `schema.yaml` for full field definitions and `partitions/mammals.md`
for a worked example.

## How to start a new partition audit (manual, pre-automation)

1. Copy `partitions/mammals.md` to `partitions/<slug>.md`.
2. Replace the partition-specific fields. The `partition:` value must match
   exactly a `group` in `data_estimates.csv`.
3. Run `curl https://api.crossref.org/works/<doi>` against the estimate
   source's DOI and the canonical tree's DOI. Set `doi_verified` / `crossref_match` accordingly.
4. Read the paper's methods section; fill the `methods:` block.
5. Search OpenAlex (`https://api.openalex.org/works?search=<clade>+phylogeny`)
   for candidate sub-clade papers; write each into `candidate_subclades`.
6. Status starts at `stub`; advance to `in_progress` once verified; to
   `verified` only when all open questions are resolved.

After Phase B ships, steps 3 and 5 above are replaced by:

```bash
python scripts/audit_partition.py init <slug>
python scripts/audit_partition.py verify <slug>
python scripts/audit_partition.py scan <slug>
```

## Pilot — Mammals

`partitions/mammals.md` is the pilot audit. It demonstrates the schema
end-to-end with real data: Burgin 2018 + Upham 2019 DOIs verified, methods
extracted from the PLOS Biology article, three candidate sub-clades
(bats / muroid rodents / marsupials) proposed with real papers.

If the Mammals schema feels right, the next pilots are **Birds** (thin
test — recent canonical tree, few gaps) and **Insects** (messy test —
multiple competing supertrees, uncertain estimate range). Schema is
frozen after those three; the remaining 24 partitions roll out without
further schema changes.

## Phases (see Phase A plan in conversation)

- **A. Schema bootstrap** — this folder. Mammals pilot by hand. Ship schema.
- **B. Automation** — `scripts/audit_partition.py` with init/verify/scan/lint.
- **C. Partition rollout** — 27 partitions, auto-init + manual review + advance to verified.
- **D. Website integration** — `site/build.py` projects audit frontmatter
  into `data.json`; new "Audit" tab in the partition detail panel.
- **E. Sub-tree acquisition** — rolling, per accepted candidate.

## Conventions

- **Slugs** are lowercase, space → underscore. `Seed plants` → `seed_plants`.
- **`provenance_group`** in `canonical_tree:` matches `data_provenance.csv`,
  which differs from the partition slug (`mammals` partition's provenance
  group is also `mammals` — but `Birds` partition has provenance groups
  `birds_mctavish` and `birds_jetz`).
- **No filenames in markdown**; reference shipped trees by their `filename:`
  field. The lint script cross-checks against `standardized/metadata.csv`.
- **Citations live in `data_sources.csv`**, not in the audit body. The audit
  references citations by `source_key`; the build script joins.
- **API responses cached** — every Crossref/OpenAlex call writes to
  `audits/fetched/<service>/<key>.json`. Replays hit the cache, do not
  re-query the API. Cache is gitignored.

## Glossary

- **Canonical tree** — the largest tree (by tip count) within a partition.
  One per partition (or `False` for partitions with no clear leader, e.g.
  the 218 Condamine 2019 family trees, which the build treats as peers).
- **Sub-clade tree** — any non-canonical tree under the same partition.
- **Estimate source** — the published-paper citation in `data_sources.csv`
  used as the denominator for "% of estimated diversity" coverage.
- **Dark-matter lineage** — a partition listed in `data_estimates.csv` with
  no shipped tree at all. These get `status: deferred` audits that record
  candidate papers but no methods block.
