# Phylo-Species Atlas — browser site

Static companion site for the atlas. No build step, no framework — just `index.html`, `app.js`, `style.css`, and a generated `data.json`. Tree files are fetched directly from `standardized/trees/`.

## Local preview

From the repo root:

```bash
python3 site/build.py              # regenerate site/data.json from CSVs
python3 -m http.server 8765        # serve the repo
open http://127.0.0.1:8765/site/   # open the page
```

## How updates flow

| Trigger | Effect |
|--------|--------|
| Push to `main` touching `site/`, `standardized/`, or `data_provenance.csv` | GitHub Actions rebuilds `data.json` and redeploys to GitHub Pages (`.github/workflows/pages.yml`). |
| Tag a release on GitHub (e.g. `v1.0.0`) | Zenodo's GitHub integration mints a new versioned DOI; the concept DOI always resolves to the latest. |

Edit `site/build.py` to change what gets serialized into `data.json`. Edit `site/app.js` / `index.html` / `style.css` for the UI.

## Architecture

- **`data.json` (~950 KB)** — summary stats, per-tree metadata (264 rows), and coverage rows (49 datasets with coverage %). Generated by `build.py` from `standardized/metadata.csv` + `data_provenance.csv`.
- **Tree files** — Newick strings fetched on demand from `standardized/trees/<name>.nwk`. The dictionary (`dictionary.csv`, 18 MB) is **not** bundled into `data.json`; the page works with the standardized numeric tip labels.
- **Plots** — Plotly.js from CDN. Two main views: coverage bar chart (clickable to pick a tree) and tip-count histogram.
- **Tree viewer** — phylotree.js from CDN. Trees with > 5,000 tips are randomly sampled before rendering; the original is always available via the download link.

## Caveats

- `data.json` is committed to the repo as a convenience (so the site works without running `build.py`). The Action regenerates it on every deploy, so don't edit it by hand.
- The species name lookup (numeric ID → standardized name) isn't exposed in v1 because `dictionary.csv` is 18 MB. If we want it, the next step is a separate `names.json` shard or an in-browser SQLite (sql.js) over the CSV.
